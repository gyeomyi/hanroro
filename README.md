# 한로로 HANRORO — 팬사이트

싱어송라이터 **한로로**의 비공식 팬사이트. 빌드 도구 없는 정적 HTML/CSS/JS에
방명록만 Supabase로 붙였습니다.

> 컨셉은 "쓰는 사람". 한로로는 가사보다 산문을 먼저 쓰는 국문학도이고,
> 3집 〈자몽살구클럽〉은 동명 소설과 세계관을 공유합니다.
> 그래서 이 사이트는 가수 팬페이지가 아니라 **한 권의 책**으로 설계했습니다.

### 음반 거르기

스물두 장을 **종류(EP · 싱글 · OST) × 연도**로 좁혀 볼 수 있습니다. 목록은 HTML에
그대로 들어 있고 `js/disco.js`가 `hidden`만 토글하므로, 자바스크립트가 죽어도
스물두 장이 전부 보입니다.

### 듣기

공식 유튜브 영상 여섯 개와 스포티파이 아티스트 플레이어. **유튜브 임베드는 처음부터
싣지 않습니다** — 표지 그림만 깔아두고 재생을 누를 때 `youtube-nocookie` iframe을
만듭니다. 누르기 전에는 유튜브로 아무 요청도 가지 않습니다.

### 문장 · 무대 · 표지

- **문장** — 인터뷰에서 실제로 한 말 넷. 전부 원문 기사를 열어 확인했고 각각 링크됩니다.
  **가사는 한 줄도 옮겨 적지 않았습니다.**
- **무대** — 다가오는 공연과 남은 날(D-4). 셋리스트는 확인된 목록이 없어 자리만 두었습니다.
- **표지** — 보유한 아트워크 스물두 장. 사진을 새로 긁어오지 않았습니다.

### 숨은 문장

`1111`을 타이핑하거나 자몽살구클럽의 `0+0=∞`를 네 번 두드려 보세요.

메인의 음반 섹션은 두 층입니다. 위쪽 큰 카드 다섯 장(EP 3 + 싱글 2)만 전용 페이지를
갖고, 그 아래 **'그 밖의 싱글' 13장과 'OST · 참여' 4편**은 목록으로만 싣고 벅스 앨범
페이지로 내보냅니다. 2022년 데뷔부터 지금까지의 발매작이 빠짐없이 들어 있습니다.

### 곡마다 붙은 산문

한로로는 가사보다 산문을 먼저 씁니다. 그 원문이 앨범 소개글에 곡별로 실려 있어서,
**EP 세 장의 스무 곡 전부에 그 글을 붙였습니다.** 곡 아래 '먼저 쓴 글'을 누르면 펼쳐집니다.
3집 〈자몽살구클럽〉은 동명 소설의 발췌라 **쪽수까지** 함께 있습니다 — 어느 장면이 어느
노래가 됐는지 그대로 따라갈 수 있습니다. 다섯 앨범 페이지 모두 라이너 노트도 있습니다.

## 실행

빌드가 없습니다. 정적 파일이라 그냥 열면 됩니다.

```bash
python -m http.server 8000
# http://localhost:8000
```

`index.html`을 더블클릭해도 동작하지만, 로컬 서버로 여는 쪽을 권합니다.


### 두 개의 디자인 시스템

**메인·방명록** — 밤/낮 두 테마. 색은 전부 CSS 변수이고 두 테마가 같은 변수 집합을
정의합니다. 팔레트 근거는 데뷔곡 '입춘' — 아직 어두운데 봄이라 부르는 절기.
먹밤 바탕 위로 자몽·살구의 여명이 트는 배색입니다.

**앨범 페이지** — 메인의 셸(헤더·밴드·푸터)을 쓰지 않습니다. `css/album.css`가
레이아웃과 색을 전부 새로 정의하고, `<html data-album="...">` 하나로 전환됩니다.
**색은 전부 실제 표지 이미지에서 뽑았습니다.**

| | 앨범 | 세계 |
|---|------|------|
| `ep1` | 이상비행 | 검정 위 전기 파랑 |
| `ep2` | 집 | 검정 위 붉은 화염 |
| `ep3` | 자몽살구클럽 | 흰 종이에 색연필 (밝음) |
| `single` | 입춘 | 역광 바다의 푸른 새벽 |
| `youandi` | 너와 나 | 하늘색과 남색 선 (밝음) |

밤/낮 토글은 앨범 페이지에 없습니다. 그 표지의 세계 하나만 입습니다.

### 링크 미리보기

7개 페이지 모두 Open Graph 태그가 있어서 카톡·트위터에 붙여넣으면 표지 썸네일과
제목이 달린 카드로 보입니다. `og:image`/`og:url`에 배포 주소
(`https://hanroro-eight.vercel.app`)가 하드코딩돼 있으니 도메인이 바뀌면 7개 파일을
전부 고쳐야 합니다.

### 접근성

- 두 테마 · 다섯 앨범 세계 **전부 WCAG AA(4.5:1) 확인**
- `prefers-reduced-motion`에서 애니메이션 · 스크롤 효과 · 진행 막대 정지
- `:focus-visible` 아웃라인 유지, 첫 탭에 '본문 바로가기' 링크
- 곡별 산문과 셋리스트는 `<details>`라 JS 없이 키보드로 열립니다
- 거르기 칩은 `<button>` + `aria-pressed`, 결과 수는 `role="status"`로 읽어줍니다
- 표지 설명은 화면에선 hover로 뜨지만 DOM에는 늘 있어 스크린리더가 언제나 읽습니다.
  hover가 없는 화면(`@media (hover:none)`)에서는 처음부터 띄워 둡니다

## 방명록

Supabase(PostgreSQL + REST). 로그인 없이 이름·내용·비밀번호로 글을 남기고,
그 비밀번호로만 수정·삭제할 수 있습니다.

- 테이블 조작은 전부 **RPC 함수**(`sign_guestbook` / `edit_guestbook` / `remove_guestbook`)를 거칩니다.
  RLS 정책상 클라이언트의 직접 INSERT/UPDATE/DELETE는 막혀 있습니다
- 비밀번호는 pgcrypto **bcrypt(cost 10)** 해시로만 저장하고, 해시 컬럼은
  컬럼 단위 권한으로 REST에서 읽을 수 없게 막아뒀습니다
- `js/guestbook.js`의 anon 키는 **공개용**입니다. 노출을 전제로 설계된 키이고
  실제 방어는 RLS와 컬럼 권한이 합니다
- 모든 사용자 입력은 `escapeHtml()`로 이스케이프합니다
- 길이·빈값 검증은 브라우저가 아니라 **서버(RPC)에서** 합니다. 비밀번호 실패가
  글 하나당 5분에 10회를 넘으면 잠깁니다
- 외부 CDN 스크립트는 버전을 고정하고 **SRI 해시**로 무결성을 검증합니다

## 앨범 좋아요

앨범 페이지마다 하트 버튼이 하나 있습니다. 로그인 없이 누를 수 있고, 다시 누르면 취소됩니다.
수는 Supabase에 앨범별로 하나씩 쌓입니다(`album_like` 테이블 + `like_album` RPC).

중복 방지는 브라우저 `localStorage`로만 합니다. 서버는 누가 눌렀는지 구분하지 않으니
정확한 집계가 아니라 **분위기용 숫자**로 봐주세요.
